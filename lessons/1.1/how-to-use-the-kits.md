# How to use the student kits (Lesson 1.1)

Every lesson comes with a student kit: a folder named after the lesson (`lessons/3.3/`, `lessons/10.4/` and so on).

## What's inside

| File | What it is |
|---|---|
| `README.md` | Start here. What the lesson did, a table of the kit's files, "Try it yourself", "You're done when" and "Good to know" |
| `prompts.md` | The exact requests typed in the lesson, in order, ready to copy, with a placeholder where your own details go |
| Cheat sheets, worksheets, checklists | The lesson's words and commands on one page, or the worksheet for its pause-and-try exercise |
| `trading-lab/` or `trading-desk/` | From Module 3 on: the files that lesson's commit added or changed, in the lab (part 1) or the trading desk (part 2) |
| Install steps | In every install lesson: exact steps for Windows, macOS and Linux |

## How to work through a lesson

1. Watch the lesson once, all the way through.
2. Open the kit's `README.md`. Read "What's in this kit", and "Before you start" where there is one.
3. Do "Try it yourself" with your own Claude, on your own computer, against your own paper account. Copy requests
   from `prompts.md` rather than retyping them.
4. Check yourself against "You're done when".
5. Use the kit's code to compare with what your own Claude built. Build your own: the kit is a reference, not a
   shortcut.

## Expect differences

Your numbers, dates, prices and Claude's answers will differ from the video: a different day, different market data,
and a model that writes every answer fresh. That's expected. What should match is the method: the checks, the tests,
and the rule that every order goes to the paper account.
